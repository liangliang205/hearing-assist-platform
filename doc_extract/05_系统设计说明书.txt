[Normal] 一、设计目标与原则
[Normal] 1.1 设计目标
[Normal] （1）支撑需求规格说明书中全部 MVP 需求（FR-01 ~ FR-08 中标注 MVP 的条目）。
[Normal] （2）在单人或小规模并发条件下稳定运行，处理链路可观测、可重试、可恢复。
[Normal] （3）音频处理、文件存储、任务队列三处保留可替换边界，便于 v1.1 引入离线频谱重映射与对象存储。
[Normal] （4）全部功能可通过 docker-compose 在干净机器上部署复现。
[Normal] 1.2 设计原则
<<TABLE 7 rows x 3 cols>>
| 原则 | 含义 | 落地方式 |
| 职责单一 | 每个服务只做一类事，边界清晰 | 业务后端不做音频算法，AI 服务不直连业务数据库 |
| 接口先行 | 先定契约再写实现 | 接口路径、数据模型、状态机在编码前冻结并写入接口规范 |
| 关注点分离 | 业务逻辑与基础设施解耦 | 存储、队列、音频增强均抽象为可替换的模块接口 |
| 工程量优先 | 以最小代价验证核心价值 | 能用浏览器原生能力实现的效果不引入离线重算（详见第五章） |
| 失败可控 | 任何环节失败都可定位与恢复 | 统一任务状态机 + 结构化日志 + 可重试机制 |
| 渐进增强 | MVP 与后续版本共用同一套骨架 | 数据库模型按 PostgreSQL 设计，开发期可用 SQLite 提速 |

<<END TABLE>>
[Normal] 二、总体架构设计
[Normal] 2.1 分层架构
[Normal] 系统采用“模块化单体业务后端 + AI 微服务”架构。前端负责交互与实时音频处理；业务后端负责用户、视频、字幕等业务数据与任务编排；AI 微服务负责识别与音频算法；存储与消息组件承担文件、结构化数据与任务传递。
<<TABLE 8 rows x 4 cols>>
| 层次 | 组成 | 职责 | 对外接口 |
| 展示层 | React 18 + TypeScript + Vite + Ant Design | 页面渲染、表单与交互、视频播放与字幕挂载、Web Audio 实时增强、结果可视化 | 调用业务后端 REST 接口；本地使用 Web Audio / HTML5 Media API |
| 接口层 | NextJS API Routes / Route Handlers | 请求校验、鉴权、参数与错误码统一处理、限流与日志埋点 | REST over HTTPS（/api/v1/*） |
| 业务层 | NextJS 服务模块 + Prisma ORM | 用户与档案、视频与字幕元数据、任务状态机、实验数据统计与导出 | 调用数据层与任务队列 |
| 任务调度层 | BullMQ + Redis | 任务入队、优先级与重试、并发控制、超时与失败标记 | 队列接口（内部） |
| AI 服务层 | FastAPI + Python + faster-whisper + ffmpeg | 音频抽取、语音识别、时间对齐、字幕生成；（v1.1）频谱重映射 | REST over HTTP（内网，/ai/v1/*） |
| 数据与存储层 | PostgreSQL、Redis、本地文件系统（v1.1 可换 MinIO） | 结构化数据持久化、缓存与队列、视频与字幕文件存储 | Prisma / 文件存储模块接口 |
| 部署与运维层 | Docker Compose + Nginx | 服务编排、反向代理、静态资源、环境隔离与健康检查 | 容器编排文件与运维文档 |

<<END TABLE>>

<<TABLE 14 rows x 4 cols>>

| 离线频域处理 | librosa / torchaudio（v1.1） | STFT 分析与频率压缩/搬移实现成熟 | 自研 numpy 实现 |
| 容器编排 | Docker Compose | 单机一键起全栈，符合个人课题部署条件 | Kubernetes |

[Normal] 字幕链路是系统的关键路径，设计上重点解决三件事：长音频的内存与耗时控制、时间信息的稳定性、异步任务与业务请求的隔离。
<<TABLE 9 rows x 4 cols>>
| 步骤 | 参与方 | 处理内容 | 异常与返回 |
| 1 | 业务后端 | 转码完成后创建字幕任务（状态=排队），写入 tasks 表 | 同一视频已有进行中任务时不重复创建 |
| 2 | 任务队列 | 任务入队，AI 服务消费 | 超时未消费由重试策略处理 |
| 3 | AI 服务 | 读取 WAV，做 VAD 切分，按静音边界切成若干片段 | 音频损坏返回 E4003 |
| 4 | AI 服务 | 逐片段调用 faster-whisper 识别，得到文本与片段时间戳 | 单片段失败按策略重试 1 次 |
| 5 | AI 服务 | 按片段偏移量累积时间戳，合并为全局分段结果 | 时间戳异常（重叠/倒退）时按序修正并记录告警 |

| 7 | 业务后端 | 更新任务状态与字幕记录，记录处理耗时与分段数 | — |
| 8 | 前端 | 轮询任务状态，完成后在播放页挂载 VTT 字幕 | 失败展示原因与重试按钮 |
