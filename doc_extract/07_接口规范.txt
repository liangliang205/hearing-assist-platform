[Normal] 二、通用约定
[Normal] 2.1 基础约定
<<TABLE 10 rows x 2 cols>>
| 项目 | 约定 |
| 基础路径 | 业务接口统一前缀 /api/v1；AI 微服务内网前缀 /ai/v1（不对外暴露） |
| 传输协议 | HTTPS（生产）/ HTTP（本地开发）；请求与响应均为 JSON，文件上传使用 multipart/form-data |
| 字符编码 | UTF-8 |
| 时间格式 | ISO 8601 带时区，如 2026-09-27T10:30:00+08:00；时长类字段统一使用毫秒整数并以 _ms 结尾 |
| 命名风格 | 路径使用小写短横线（kebab-case），JSON 字段使用小驼峰（camelCase） |
| 鉴权方式 | 请求头 Authorization: Bearer <token>；除注册、登录、健康检查外均需鉴权 |
| 幂等性 | GET 幂等；上传与创建任务通过唯一键或客户端标识保证幂等；删除操作幂等 |
| 限流 | MVP 不做接口限流；上传接口限制单次文件大小与并发数 |
| 版本策略 | 路径中携带版本号；破坏性变更升版本，增量字段不升版本 |

<<END TABLE>>

[Normal] 2.2 统一响应结构
<<TABLE 1 rows x 1 cols>>
| // 成功响应 / { / "code": "0", / "message": "ok", / "data": { /* 业务数据，可能是对象、数组或 null */ }, / "traceId": "b1c2d3e4-5f60-7a8b-9c0d-1e2f3a4b5c6d" / } / // 失败响应 / { / "code": "E2001", / "message": "视频上传失败：文件写入存储时发生错误", / "data": null, / "traceId": "b1c2d3e4-5f60-7a8b-9c0d-1e2f3a4b5c6d" / } |

<<END TABLE>>
[Normal] · code 为字符串，"0" 表示成功，其余为错误码（见第五章）。
[Normal] · message 为面向用户的中文提示，前端可直接展示；不得包含堆栈、SQL 或内部路径。
[Normal] · data 在失败时统一为 null；在列表接口中为分页对象。
[Normal] · traceId 用于日志追踪，前端在报错提示中可作为“错误编号”展示，便于排查。

[Normal] 2.4 通用状态码
<<TABLE 14 rows x 3 cols>>
| HTTP 状态码 | 含义 | 使用场景 |
| 200 | 成功 | 查询、更新、删除成功 |
| 201 | 已创建 | 注册、上传、创建任务成功 |
| 202 | 已接受 | 异步任务已入队 |
| 400 | 请求参数错误 | 参数校验失败、格式不合法 |
| 401 | 未认证 | 缺少 Token、Token 无效或过期 |
| 403 | 无权限 | 访问他人资源或需要管理员权限 |
| 404 | 资源不存在 | 资源 ID 不存在或不属于当前用户 |
| 409 | 冲突 | 邮箱已存在、重复提交同一任务 |
| 413 | 请求体过大 | 上传文件超过大小限制 |
| 415 | 媒体类型不支持 | 上传文件格式不被支持 |
| 429 | 请求过于频繁 | 预留，MVP 暂不使用 |
| 500 | 服务内部错误 | 未预期异常 |
| 503 | 依赖不可用 | 数据库、Redis 或 AI 服务不可用 |

<<END TABLE>>
