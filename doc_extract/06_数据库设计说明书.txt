[Normal] 一、概述
[Normal] 1.1 设计目标
[Normal] （1）完整支撑需求规格说明书中的 MVP 功能需求与实验数据采集需求。
[Normal] （2）结构清晰、命名一致，便于单人维护与后续扩展（v1.1 离线频谱重映射、v1.2 字幕编辑与预设）。
[Normal] （3）兼顾开发期 SQLite 与部署期 PostgreSQL 的兼容性，避免迁移时重构。
[Normal] （4）关键查询有索引支撑，避免视频列表、任务列表、实验数据导出等操作出现全表扫描。
[Normal] 1.2 数据库环境
<<TABLE 8 rows x 2 cols>>
| 项目 | 内容 |
| 数据库类型 | PostgreSQL 14 及以上（部署环境）；SQLite 3（仅本地开发加速） |
| 字符集与排序 | UTF8；排序规则默认（中文内容以全文存储为主，不做排序依赖） |
| 访问方式 | 通过 Prisma ORM 访问，不使用手工拼接 SQL |
| 迁移方式 | Prisma Migrate 管理版本化迁移，部署时执行 migrate deploy |
| 时间存储 | 统一使用 timestamptz（带时区），应用层按 UTC 存储、按本地时区展示 |
| 主键策略 | 自增整数主键，便于索引与调试；对外暴露的资源使用独立业务 ID |
| 软删除策略 | MVP 不采用软删除，删除即级联清理；如后续需要审计再引入 deleted_at |

<<END TABLE>>
[Normal] 1.3 命名与设计约定
<<TABLE 10 rows x 3 cols>>
| 对象 | 约定 | 示例 |
| 表名 | 小写英文复数，单词间下划线分隔 | users、subtitle_segments、enhancement_logs |
| 字段名 | 小写英文，单词间下划线分隔 | created_at、duration_ms、video_id |
| 主键 | 统一命名 id | id |
| 外键 | 引用表名单数 + _id | user_id、video_id、task_id |
| 布尔字段 | 以 is_ 或 has_ 前缀 | is_active、is_current |
| 时间字段 | 以 _at 结尾 | created_at、finished_at |
| 状态与类型 | 使用 varchar 存储枚举值，取值在应用层强约束 | status = 'queued' | 'processing' | ... |
| JSON 配置 | PostgreSQL 使用 jsonb，SQLite 使用 text | config_json、config_snapshot |
| 敏感数据 | 密码仅存哈希；不存储明文凭证 | password_hash |

[Normal] 表 4-1  完整性约束与业务规则
[Normal] 4.1 一致性事务要点
[Normal] （1）切换生效听力配置：同一事务内先将该用户其他配置 is_current 置 false，再置目标配置为 true，避免并发下出现两份生效配置。
[Normal] （2）创建任务：先按 task_key 查询，不存在则插入；唯一索引冲突时返回既有任务，保证幂等。
[Normal] （3）视频删除：事务内删除 videos 记录（级联 tasks / subtitles / enhancement_logs / video_metrics），提交成功后再清理磁盘文件，避免文件已删而记录保留。
[Normal] （4）字幕写入：先写入 subtitle_segments，再更新 subtitles 的 segment_count 与 avg_confidence，最后写入 SRT/VTT 文件路径。
[Normal] （5）自测保存：写入 hearing_tests 明细与 hearing_profiles 配置在同一事务内完成，防止出现有明细无配置的中间状态。

[Normal] 5.2 性能与索引策略
[Normal] （1）视频列表：user_id + created_at DESC 复合索引支撑分页与排序，避免排序时全表扫描。
[Normal] （2）任务查询：video_id + task_type 定位阶段状态；status + created_at 支撑管理端查看积压任务。
[Normal] （3）实验数据导出：user_id + created_at DESC 支撑按时间范围筛选；导出时限制单次行数并在界面提示。
[Normal] （4）自测历史：user_id + tested_at DESC 支撑倒序列表；session_id 支撑按次聚合做重复性分析。
[Normal] （5）字幕分段：subtitle_id + seq 保证顺序读取，生成字幕文件时不额外排序。
[Normal] （6）JSON 字段（thresholds_json、config_snapshot、params_json）：MVP 阶段不做 GIN 索引，仅在应用层读取整体对象；若后续需要按参数检索再补充。
[Normal] 5.3 备份与恢复
[Normal] · 开发期：使用 pg_dump 定期导出结构与数据，脚本纳入仓库的 scripts/ 目录。
[Normal] · 部署期：数据卷单独挂载，容器重建不丢失数据；升级前先执行一次备份。
[Normal] · 文件与数据库一致性：以数据库记录为准；若出现文件缺失，管理端提供“重建派生文件”入口（v1.1）。
[Normal] · 演示前：提前完成一次完整备份，避免演示当天因数据问题无法恢复。
