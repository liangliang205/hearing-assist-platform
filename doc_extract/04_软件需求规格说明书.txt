[Normal] 一、引言
[Normal] 1.1 编写目的
[Normal] 本文档定义听障辅助视频处理及听力自测平台的功能需求、非功能需求与约束条件，为概要设计、详细设计、编码实现、测试用例编写和最终验收提供统一的需求基线。本文档的读者包括：开发者本人、指导教师、企业导师与学院检查人员。
[Normal] 1.2 项目背景
[Normal] 听力损失会影响个体的信息获取、交流与社会参与，而现有数字视频的无障碍支持多以语音文字转写为主，对音乐、环境声、非语音提示等听觉信息覆盖不足；同时不同听障用户对字幕呈现方式与声音提示的需求存在差异。另一方面，移动听力测试研究已表明智能手机与网页端听力自测具备应用潜力，但结果受设备与环境影响，需要明确其辅助筛查定位。
[Normal] 本课题在软件工程层面把三件事整合到同一平台：AI 字幕生成、个性化听力自测、实验性频谱重映射，并通过模块化架构提高扩展与部署能力。
[Normal] 1.3 术语与缩写

[Normal] 二、总体描述
[Normal] 2.1 系统定位与边界
[Normal] 系统是一个 Web 平台，核心价值链为：用户上传视频 → 系统自动生成字幕 → 用户完成听力自测形成听力配置 → 系统依据配置对音轨做补偿式增强 → 用户在原音与增强之间对比试听 → 结果与评价被记录。
<<TABLE 5 rows x 2 cols>>
| 边界类型 | 内容 |
| 系统做什么 | AI 字幕生成；个性化听力自测与配置管理；视频上传、转码与在线播放；依据听力配置的音频增强与原音/增强对比；处理过程与评价数据的记录与导出 |
| 系统不做什么 | 不做医疗诊断，不输出临床听力损失等级结论；不替代专业助听设备；不提供实时通话或直播字幕；不提供社交与内容分发功能 |
| 关键定位说明 | 听力自测定位为辅助筛查与个性化参数采集，结果仅用于本系统的音频增强调节；频谱重映射为实验性音频处理策略，其映射规则与参数由本课题自行设计，不等同于临床助听器中的标准频率降低算法 |
| 合规与伦理 | 上传的视频与听力数据仅用于本课题研究；演示素材使用自制或已授权样本；自测页面明示用途与免责说明；用户可删除自己的数据 |

<<END TABLE>>

[Normal] 2.4 主要业务流程
[Normal] （1）听力自测流程：登录 → 阅读免责说明 → 设备与音量校准 → 逐频点播放测试音 → 用户反馈（听见/未听见）→ 系统计算可听区间 → 生成并保存听力配置 → 展示结果曲线。
[Normal] （2）视频处理流程：登录 → 上传视频 → 系统校验并保存 → 异步转码与音频抽取 → 触发字幕任务 → 识别与时间对齐 → 生成 SRT/VTT → 用户在线播放并挂载字幕。
[Normal] （3）音频增强流程：选择视频 → 读取当前听力配置 → 计算各频段增益 → 实时音频处理 → 用户在原音与增强之间切换试听 → 调整强度并记录参数与评价。
[Normal] （4）任务状态流转（异步处理统一模型）：排队 → 处理中 → 成功 / 失败（可重试）；同一视频的字幕任务在转码完成前保持排队状态。
<<TABLE 7 rows x 3 cols>>
| 当前状态 | 触发条件 | 下一状态 |
| 排队 Queued | 任务创建成功且前置任务已完成 | 处理中 Processing |
| 排队 Queued | 前置任务失败或超时 | 失败 Failed |
| 处理中 Processing | 处理脚本正常返回 | 成功 Succeeded |
| 处理中 Processing | 处理异常或超过超时阈值 | 失败 Failed |
| 失败 Failed | 用户点击重试 | 排队 Queued |
| 成功 Succeeded | — | 终态，不再流转 |

<<END TABLE>>

[Normal] 七、需求约束与假设
[Normal] 7.1 约束条件
[Normal] （1）人力约束：单人开发，全部工作由开发者本人承担，总投入约 20 小时/周、12 周约 240 小时。
[Normal] （2）技术约束：AI 推理以 CPU 为主，模型规格受本机资源限制；音频实时处理依赖浏览器 Web Audio API 能力。
[Normal] （3）时间约束：MVP 须在第 12 周前形成可演示、可部署的成果，第 13—16 周用于论文与系统完善。
[Normal] （4）合规约束：系统不得输出医疗结论；用户音频与听力数据仅用于本课题；演示素材须自制或已授权。
[Normal] （5）交付约束：系统须能在干净机器上按文档完成部署与演示。
[Normal] 7.2 假设与依赖
[Normal] （1）假设用户的播放设备能够正常输出 500 Hz—8 kHz 的声音；无法保证时以界面提示方式说明限制。
[Normal] （2）假设上传视频包含可识别的语音内容；纯音乐或强噪声视频的字幕质量不作保证。
[Normal] （3）依赖开源组件：faster-whisper、ffmpeg、librosa/torchaudio（v1.1）、BullMQ、Prisma；组件版本在设计与部署文档中固定。
[Normal] （4）依赖用户网络环境稳定完成上传；本期不提供断点续传。
[Normal] （5）听力自测结果受设备与环境影响，其一致性边界在论文的测试与实验章节中说明。
